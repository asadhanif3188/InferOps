## 2. After merge, before the tag

Run on a clean checkout of `main`, in Git Bash, from the repository root, in one shell:
section 3 uses `$CANDIDATE`. `set -e` stops the block at the first check that fails; fix
it in a new change, and that change's merge becomes the candidate.

```sh
set -e
# 2.1 The candidate is the merge of V1-S5-008-PR1, and the checkout is clean.
git fetch origin --tags
git checkout main
git pull --ff-only origin main
CANDIDATE="$(git rev-parse HEAD)"
git log -1 --format='%H %s' "$CANDIDATE"   # the merge or squash of V1-S5-008-PR1
test -z "$(git status --porcelain --untracked-files=all)"

# 2.2 No v1.0.0 tag exists here or on the remote.
test -z "$(git tag -l v1.0.0)"
test -z "$(git ls-remote --tags origin refs/tags/v1.0.0)"

# 2.3 The version is 1.0.0 in the one place it is declared, and the lock agrees.
grep -n '^version = "1.0.0"$' pyproject.toml
uv lock --check

# 2.4 The gate still passes, over the frozen digests.
uv run --locked python -m tools.evidence_index --gate
# expect: COMPLETE V1-S5-013 ..., FROZEN V1-S5-013-PR2 ...,
#   evidence set  1d40b33fd79d7b6436c35cfe1fc4ec943a8b82fc77ad1da7cd5d96bb2a5ac23a
#   evidence pack 652e9051161d38e6dd2e77306a431bf96d863a262cc4b0dab15c0518ba920ad2

# 2.5 The release, the case study, and the evidence still agree.
uv run --locked python -m pytest tests/testing/test_release.py \
  tests/testing/test_case_study.py tests/testing/test_evidence_publication.py -q

# 2.6 Private vulnerability reporting is enabled on the repository.
test "$(gh api repos/asadhanif3188/InferOps/private-vulnerability-reporting --jq .enabled)" = true
set +e
```

2.7 The hosted `checks` workflow has passed on `$CANDIDATE`: the repository's Actions page,
or `gh run list --commit "$CANDIDATE" --workflow checks.yml`, shows a successful run for
that exact commit. A run on the pull request's head is not the candidate.

## 3. Tag and release

Only after every check in section 2 passed, by the `repository-maintainer` role. This is
the act that approves the candidate; there is no other approval artifact.

```sh
git tag -a v1.0.0 "$CANDIDATE" \
  -m "InferOps v1.0.0" \
  -m "Evidence pack sha256:652e9051161d38e6dd2e77306a431bf96d863a262cc4b0dab15c0518ba920ad2" \
  -m "Release notes: docs/releases/v1.0.0.md"
git show --no-patch v1.0.0
git push origin v1.0.0

gh release create v1.0.0 --verify-tag --title "InferOps v1.0.0" --notes \
"The first versioned release of InferOps. The notes, the frozen evidence it is cut over,
and every limitation are in docs/releases/v1.0.0.md at this tag:
https://github.com/asadhanif3188/InferOps/blob/v1.0.0/docs/releases/v1.0.0.md

Evidence pack sha256:652e9051161d38e6dd2e77306a431bf96d863a262cc4b0dab15c0518ba920ad2.
Every real result is one provider, one Windows host, CPU only, one replica; InferOps
is not a production-ready platform. No image, package, chart, or model is published."
```

No file is attached: nothing but the tag and the source archives is published, as
