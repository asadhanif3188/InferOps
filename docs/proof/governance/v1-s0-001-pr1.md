## Commands and results

### Whitespace

```text
git diff --check main...HEAD
git ls-files -z '*.md' | xargs -0 grep -n '[[:blank:]]$'
git ls-files -z '*.md' | xargs -0 grep -n "$(printf '\t')"
```

Results: `git diff --check` produced no output. Both scans returned no matches
across all tracked Markdown. Each scan was confirmed against a positive control
file containing a trailing space and a hard tab, so a silent no-op is excluded.

### Relative Markdown links

The POSIX and PowerShell link checks published in
[CONTRIBUTING.md](../../../CONTRIBUTING.md) were both executed verbatim against the
tracked Markdown set. Each enumerates `git ls-files '*.md'`, drops fenced code
blocks, extracts Markdown link destinations, excludes HTTP(S), `mailto:`, and
same-document anchors, and resolves every remaining path relative to the directory of
the file that contains it.

Results: both variants reported `PASS` with no broken links over 12 tracked Markdown
files and 19 resolved relative links.

Three defects were found in earlier revisions of the check and are recorded here
rather than discarded. No failed or superseded result is represented as proof.

1. The first revision inspected fenced code blocks and reported a false positive by
   matching the `](` sequence inside its own POSIX command sample. Both variants now
   skip fenced blocks.
2. The POSIX variant iterated an unquoted command substitution, so a tracked file
   name containing a space was split into separate tokens. Reproduced in a scratch
   repository: the check silently missed a genuinely broken link. The variant now
   reads NUL-delimited paths.
3. The POSIX variant recognised fences only at column zero while the PowerShell
   variant allowed leading whitespace. Reproduced in the same scratch repository: an
   indented fenced sample produced a false positive under the POSIX variant only.
   Both now accept indented fences.

After these corrections both variants were rerun and agree.

## Limitations and skipped checks

- No repository-approved Markdown linter or link-checking tool exists yet, and none
  was installed for this pull request. Task-runner, linter, and continuous-integration
  selection are deliberately left to their own decisions, so the published checks are
  manual shell commands rather than committed tooling.
- No continuous-integration workflow exists, so this evidence is local and is not a
  remote required check.
- The checks were executed on one Windows host. The POSIX variant was run under MSYS2
  bash on that same host and has not been executed on Linux or macOS.
- Remote branch protection, issue labels, review enforcement, and private reporting
  channels were not configured or tested. The repository therefore documents
  conventions it cannot yet enforce.
- No runtime, model, container, Kubernetes, schema, API, telemetry, cost, or security
  experiment was authorized or performed.
- The restricted-source comparison cannot be reproduced from the public repository
  alone, because its inputs are deliberately withheld. A public reader must take that
  result on trust; every other result recorded here is independently reproducible from
  this repository.
- The published link checks are documentation aids, not hardened tooling. A relative
  link target containing a parenthesis is still truncated at the first closing
  parenthesis in both variants, as stated in the contribution guide.
- Legal review of the MIT license was not performed.
