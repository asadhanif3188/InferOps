replica of each tier, this chart installed, loaded the pinned model, returned a
real completion through its own Service, upgraded, rolled back, replaced a
deleted serving pod against the surviving claim, and uninstalled without residue.

That certifies nothing about kind, about any other host, or about more than one
replica -- the multi-replica profile was refused at the capacity gate on that
host. docs/serving/kubernetes-real-inference-certification.md is the procedure
and docs/proof/ holds the records.

What this chart does NOT install, so that a reader is not left inferring it:

  - the namespace and the model cache claim. Those are Terraform's, this release
    is a guest in them, and helm uninstall leaves them exactly where they are.

What it DOES install, which an earlier version of this message denied:

  - the model acquisition job (V1-S3-003), as a pre-install,pre-upgrade hook that
    fills the claim and removes itself when it succeeds;
  - NetworkPolicy objects (V1-S3-004). They are created; whether the local
    network plugin ENFORCES one is a separate question and the answer is still
    no. See docs/proof/security/v1-s3-004-pr1-network-policy-enforcement.md;
  - the telemetry scrape configuration and, when telemetry.collection.collector
    .deploy is true, a release-scoped collector that reads it (V1-S3-007). Its
    series are in an emptyDir and go with its pod.

Asking whether it actually answers, which a completed rollout does not tell you:

  helm test inferops --namespace inferops-release

Reaching the API:

  kubectl --namespace inferops-release port-forward svc/inferops-inferops-llm 8090:8090

There is no ingress and no load balancer. V1 installs neither.

Removing it. `helm uninstall` removes this release and nothing else: the
namespace and the model cache claim are Terraform's and outlive it by design.
