## The sequencing deviation

**The intended order.** The project's experiment procedure is not published in this
repository. For a result-bearing run, it sets this order: check the raw evidence for
completeness; compute the verdicts with the versioned analysis; compare the verdicts with
the frozen criteria; assign the outcome states; write the limitations; have the result
reviewed independently and record any correction additively; then update the claim and
evidence register. This record is the first file in this repository to state the last
two steps. No code enforces the order.

## The claim wording and E01-AC5

E01-AC5, as freeze revision 2 states it:

> No claim-relevant workload intent is written by hand after rendering:
> admit_manual_values admits the hand-written values with no finding; every chart value
> that a workload-intent context value renders to, or that is derived from
> workload-intent context values only, is in the generated values file; no hand-written
> string contains one of those generated values of eight characters or more; and the
> generated and hand-written values, merged over the chart's defaults, equal the V1 real
> values merged the same way, except telemetry.deploymentEnvironment, which is local in
> V2 and dev in V1 as the V1 synchronous compatibility record states.

The second-run claim's statement, as the register holds it at the reviewed revision:

> The committed evidence of the second run of the frozen E01 static parts, the first under
> freeze revision 2, records that the runner and the inferops package were imported from
> the merged checkout it executed and that every repository module file it loaded was a
> pinned input, and holds two renders of the V1 synchronous reference contract on its
> local binding, written by two processes, that are byte-identical and record their
> sources; no hand-written string that contains a generated workload-intent value; a
> render after a replica-range change that differs only in the values and release fields
> that change owns; and, for each of seven registered invalid or conflicting inputs, two
> identical refusals that match the registered one and no output directory.

| | Clause |
|---|---|
| E01-AC5 | "no hand-written string contains one of those generated values **of eight characters or more**" |
| The claim | "no hand-written string that contains a generated workload-intent value" |

The claim omits `of eight characters or more`. The run's 22 workload-intent targets
include `telemetry.deploymentEnvironment`, which is `local`, and
`runtime.resources.limits.cpu`, which is `6`. The hand-written values of the reference
workload hold three strings that contain one of them:

| Hand-written value | Its string | Generated value it contains |
|---|---|---|
| `api.image.repository` | `localhost/inferops-api` | `local`, from `telemetry.deploymentEnvironment` |
| `api.image.digest` | `sha256:7961c9f9…` | `6`, from `runtime.resources.limits.cpu` |
| `model.integrity.verifyOnStart` | `sha256` | `6`, from `runtime.resources.limits.cpu` |

No hand-written string contains a generated value of eight characters or more. The
frozen analysis states the reason for the limit beside its constant: shorter values occur
inside unrelated strings. So the review found nothing against the run's verdict on
E01-AC5, and the claim's clause is broader than the criterion.

The table lists generated values that are strings, which is what the frozen analysis
compares and what the reviewer searched. The second review of this change added one case
the reviewer did not list: `runtime.replicaCount` is the integer `1`, and the digit `1`
occurs in `api.image.digest` and in `model.alias`, `qwen3-1.7b-q8_0`. It is one more
instance of the same defect, not another defect.

**Where the clause is.** The reviewer listed the register, the register page, and both
dashboard copies. The author of this record found two more copies of the claim's
statement: in the evidence index, and in the eighth ledger's added claim. The qualifier is
present in freeze revision 2, the result page, the claim's own evidence record, and the
validation record.

**What the correction is, and who owns it.** `V2-S2-005-PR2` is to narrow the claim to
the frozen wording through the register's additive mechanism. It is to start from a
revision that contains this record. Neither has happened yet.
