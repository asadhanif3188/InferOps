## What this record does not establish

- **That the release carries any new evidence.** A release number adds none: every
  result it points to is a record in the pack it was cut over, and this record measured
  nothing about the platform.
- **That nothing but the tag and the source archives is published.** No file is
  attached to the release, and the release notes say no image, package, chart, or model
  is published; no package or image registry was read, and no source archive was
  downloaded or compared with the tag's tree.
- **That the release will stay as it was read.** The release and the setting are state
  on the hosting service, which its maintainer can edit or delete; a tag object cannot
  change under its identifier, but a ref can be deleted or pointed elsewhere.
- **That the checks before the tag were run in the order the checklist gives.** No record
  of the maintainer's own run of checks 2.1 to 2.6 exists in this repository.
- **That anybody outside this repository has reviewed the release.** Nobody has.

## Limitations

- **One reading, at one moment.** Every hosting-service value is what an unauthenticated
  read returned between 10:59:44 and 10:59:54 UTC on 2026-09-27.
- **Read after the fact.** The gate and the release checks were rerun at the tag after it
  was created, on one Windows host, with `uv` against its local cache.
- **Not repeatable from a file alone.** The commands are in the transcript, and repeating
  them reads the hosting service as it is then, not as it was.

## What the evidence model cannot yet represent

`C0` fits what was done: artifacts were inspected, and the behaviour the claim concerns
was not executed by this record. Three things about it do not fit the vocabulary the
register uses, and are left as they are rather than stretched:

- **Environment.** The register's environments are `repository-only`, local and cloud
  execution environments, and organizational production. A read of a hosting service is
  none of them. The record says `repository-only`, the nearest, and its note says what
  was actually read.
- **Evidence class.** `local-static` excludes the network and the clock, and two of these
  reads used the network and return what the service holds at the moment of reading.
  The security scan's claim is the nearest precedent: a `C0` record whose tool read a
  vulnerability database from outside the repository, and whose limitation says the
  result depends on when it was read.
- **Mutable external state.** A record can pin the tag object by its identifier. It has
  no field for state it cannot pin, such as a release or a repository setting; that is
  carried in its limitations.

None of this is changed here. A later change to the evidence model may add an
environment or a class for reads of a hosting service.
